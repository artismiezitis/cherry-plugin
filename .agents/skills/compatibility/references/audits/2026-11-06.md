## Coverage boundaries and unresolved behavior

- Third-party APIs, credentials and external CDN responses were not validated. Browser regression checks blocked external network assets to isolate local behavior. The Instagram widget still targets its historical client-ID API; migrating it to a current provider API is separate work.
- Twenty Twenty-One establishes runtime behavior and a neutral render baseline. It does not supply Cherry's Bootstrap styling/interactions. No actual Cherry parent/child theme was provided or tested, so theme-specific styling, tabs/collapse behavior and template overrides are not certified by this run.
- Cherry's extra visibility form controls remain in the classic Widgets interface; the new block Widgets page and legacy previews load, but a new block-inspector visibility UI was not implemented. Historical author-rule semantics remain unchanged, as noted in the [functionality reference](../php-wordpress.md).
- The TinyMCE picker, every media format, multilingual/shop integrations, multisite, all older WordPress versions, and arbitrary plugin combinations were not exhaustively executed. PHP 8.6 prereleases and future releases are outside this matrix.
- This was a compatibility implementation and regression run, not a comprehensive security audit. The original import/export authorization and storage architecture were not comprehensively redesigned or audited.

Operating details belong in the [compatibility reference](../php-wordpress.md), and reproducible setup remains in the [README](../../../../../README.md).
